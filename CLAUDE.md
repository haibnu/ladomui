# Ladom UI

React design system built from the Figma file "Ladom UI Design System v1.0" (file key `VCJ6ew9Vk1gAqfnvQ1gfOz`). See PLAN.md for scope, decisions and phases.

## Rules
- Follow the Figma file exactly. Do not invent styles, colors or spacing.
- Colors, spacing, radius, typography and other visual values come from design tokens (CSS variables), never hard-coded in components.
- Styling is CSS variables + CSS Modules. No Tailwind.
- Components are plain React and must not depend on Next.js APIs. Next.js is only used by apps/docs.
- Mobile components are out of scope for now.
- Before committing a component, compare it with the Figma screenshot of its page (node ids are listed in PLAN.md).
- Keep commits small; one component or token group per commit.

## Tokens
- `packages/tokens/figma/variables.json` and `styles.json` are a raw export of the Figma variables and styles. Do not edit by hand; re-export instead. `figma/pages.json` holds values transcribed from Figma pages that are not variables (animation, border), with their node ids.
- Code-side decisions that are not in Figma: `figma/typography-bindings.json` (font Hanken Grotesk, missing typography variables and bindings), `config/breakpoints.json` (Mobile < 768px, Tablet < 1280px), `config/legacy-styles.json` (legacy Figma paint styles mapped to theme variables).
- `css/*.css` and `meta/tokens.json` are generated by `pnpm --filter @ladom/tokens build` (`scripts/build.mjs`); never edit them. The build fails if a Figma variable is not assigned to exactly one token group.
- Modes: Figma Desktop/Tablet/Mobile follow the breakpoints (`data-device` forces one); Dark theme is opt-in with `data-theme="dark"` (the Figma Dark mode is not final); Narrow density with `data-density="narrow"`. All on `<html>`.
- Apps load Hanken Grotesk themselves and expose it as `--font-hanken-grotesk` on `<html>`.
- Not in Figma, so no tokens yet: z-index, the bounce-y timing function.

## Icons
- `packages/icons/icons.json` is the source of truth: each Ladom icon name maps to one Tabler icon (`tabler`, optional `style: "filled"`), or to a custom icon (`source: "figma"`, SVG in `figma/svg/`). `pending: true` entries are not in the system yet and still need a decision.
- Never use `@tabler/icons-react` or other icon sets directly; add the icon to `icons.json` instead.
- `src/icons/*`, `src/index.ts` and `src/all.ts` are generated by `pnpm --filter @ladom/icons build`; never edit them.
- `pnpm --filter @ladom/icons figma:export` re-reads the Figma Icons page and the custom SVGs through the Figma REST API (needs `FIGMA_TOKEN` in `.env.local`; never print or commit it).

## Docs site (apps/docs)
- Public site for ui.ladom.co, in English and Turkish: every page lives under `app/[lang]/` and exists at `/en/...` and `/tr/...`. `/` redirects by Accept-Language (Turkish -> `/tr`, else `/en`).
- UI strings live in `apps/docs/i18n.ts` (one dictionary per language); longer page copy is written per language in the page itself. Add every new string in both languages. Token and icon names stay in English.
- Docs chrome lives in `apps/docs/components/`; import with `@/components/...`.
- The logo (`components/Logo.tsx`) is rebuilt from the "Ladom UI" heading on ladom.co; do not replace it with the Figma Brand component.

## Releasing and deploying
- The design packages stay private. Apps get Ladom UI with the `ladom-ui` CLI (`packages/cli`, dependency-free, the only npm package; `npm publish` from there), which copies files from the registry, shadcn/ui style. Updates are pulled, not pushed: each item has a content hash, `ladom-ui.json` records the hash of every file the CLI wrote, and `update` replaces only untouched files (`diff` shows the rest). Bump `packages/cli` and publish after CLI changes.
- `scripts/registry/build.mjs` builds `apps/docs/registry/` (gitignored: `registry.json`, `tiers.json`, `licenses.json`) from the packages; `scripts/registry/items.json` gives each component its tier. Internal parts (Floating, Brand) are free when a free item needs them; the build fails if a free item depends on a Pro one. Add every new component to `items.json`.
- `apps/docs/app/r/[file]/route.ts` serves the registry: free items to everyone, Pro items only with `Authorization: Bearer <key>` whose SHA-256 is in `LADOM_UI_PRO_KEYS` (Vercel env, comma-separated hex). `node scripts/registry/new-key.mjs` makes a key; never commit keys.
- Licenses: `LICENSE.md` (MIT for the free tier and the CLI) and `LICENSE-PRO.md` (draft, needs legal review). Each copied file starts with its tier's license line; the docs page is `/[lang]/docs/license` (`/license` redirects).
- `scripts/bundle-package.mjs` is only used by `scripts/claude-design/` now.
- The docs deploy on Vercel: project `ladom-ui` in the "Ladom's Projects" team, root `apps/docs`, domain ui.ladom.co (DNS on Cloudflare: a CNAME to Vercel). Pushes deploy; `main` is production.
- `skills/ladom-ui/SKILL.md` is the Claude Code skill for projects that use Ladom UI (the registry serves it for `npx ladom-ui skill`); keep it in step with the components.
- The claude.ai design system (https://claude.ai/artifact/GMGcccbEoBzuj6Q9Q5ZJdD) is built with `scripts/claude-design/` (see its README); re-sync it after token or component changes.

## Commands
- `pnpm install`, then `pnpm dev` (builds tokens, starts the docs app).
- `pnpm build`, `pnpm typecheck`.
- `node scripts/registry/build.mjs` rebuilds the registry (the docs scripts run it too).
